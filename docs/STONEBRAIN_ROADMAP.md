# 石頭腦 StoneBrain — 品牌與成長 Roadmap

> 初版：2026-11-25（Asia/Taipei）｜狀態：規劃建立，分階段執行
> 本文件是公開的產品與內容路線圖；不記錄帳號憑證、復原資料、私人聯絡方式或未公開商業資訊。

## 1. 目標與已確認方向

- [x] 品牌方向：由個人技術 Blog 升級為「石頭腦 StoneBrain」技術知識品牌。
- [x] 內容方向：AI、Data Engineering、Software Engineering、System Design、DevOps、Open Source；以初學者可理解、可重現的教學為核心。
- [x] 既有文章、截圖及研究成果作為第一批內容資產，保留歷史與原有價值。
- [x] 視覺方向：黑白極簡、保留淺色/深色模式，幾何石頭吉祥物兼具親切與專業。
- [x] 動畫方向：保留紙張收納概念，延伸吉祥物思考、研究及學習循環。
- [ ] 標準字、吉祥物最終造型、英文標語、帳號名稱與網域的正式確認。
- [ ] 名稱、商標、帳號及網域可用性查核（未查核前不得視為已取得）。

候選標語：技術很硬，學習不用。英文：Make technology understandable.
角色暱稱候選：小石。以好奇、認真、偶爾困惑但持續學習的角色人格經營。

## 2. 執行原則

1. 先用原 repository 與原網址完成品牌轉換，再評估搬遷；不可因品牌更名而遺失文章或破壞連結。
2. 每階段以小型 PR、可回退變更及明確驗收進行；變更前檢查現況與既有未合併工作。
3. 個人帳號與品牌對外聯絡分離；以品牌資源、最小權限、雙因素驗證與安全復原管理。不提交任何密碼、Token、復原碼或私人聯絡資訊。
4. 帳號註冊、商標申請、付費、網域購買、repository 轉移及 DNS/正式網址切換，須由品牌管理者確認並完成必要的驗證。
5. 網站優先使用輕量 SVG/CSS 動畫；社群使用 GIF/MP4，提供靜態替代並尊重 reduced-motion。
6. 技術內容須以官方文件、GitHub、可靠技術資料及可行的實測為依據；明確區分實測與未實測結果。

## 3. 階段與驗收

時間以啟動後週次作為建議節奏，不是承諾的上線日期。遇到外部帳號或審核依賴可並行處理其他工作。

### P0 — 品牌基礎與資產盤點（第 1 週）

- [x] 建立版本化 Roadmap 初稿。
- [ ] 盤點既有文章數量、分類、網址、圖片、文章 metadata、部署 workflow 及未合併 PR。
- [ ] 記錄網站現況與主要頁面（桌面、手機、黑白模式）作為回歸測試基準。
- [ ] 查核名稱、候選社群 handle、網域及商標；記錄來源、日期及結果，不以搜尋不到當作可註冊。
- [ ] 管理者建立品牌專用 Email、復原方式及 2FA；個人 Email 不作公開品牌聯絡地址。
- [ ] 選定一致的社群 handle 並建立必要帳號，優先 Threads、Instagram；LinkedIn、Facebook、YouTube 視資源逐步擴展。
- [ ] 定稿吉祥物、Logo（組合版/文字版/圖示版/反白版）、favicon、黑白配色與字型規範。
- [ ] 定稿動畫：知識收納、石頭腦啟動、學習循環；明確標示 GIF 原型與正式可用素材。

**驗收：** 品牌資產與命名有版本管理、既有內容有基準清單；帳號及名稱查核有記錄。外部帳號未完成時不阻擋本地品牌設計。

### P1 — 現有網站品牌化（第 2 週）

- [ ] 更新網站標題、品牌名稱、Logo、favicon、About、首頁標語及 footer。
- [ ] 保留原本文章路徑、文章內容、圖片、搜尋、分類、標籤及深淺模式。
- [ ] 加入吉祥物的靜態/互動素材；預設安靜，hover 或明確互動時才播放，行動裝置提供合適替代。
- [ ] 首頁/Logo 動畫延續紙張收納概念；404、搜尋、載入等互動視優先級逐步導入。
- [ ] 更新文章封面、Open Graph、分享圖片及 SEO metadata；檢查 canonical、sitemap、RSS、robots。
- [ ] 在原有 CI/CD 下完成 build、lint（依專案腳本）、部署與站點 smoke test；所有相關 stage 成功才算完成。
- [ ] 確認桌面/手機、深淺模式、鍵盤操作、圖片、搜尋與既有文章連結；記錄回退方式。

**驗收：** 原文章數量及路徑無非預期變動，主要功能正常；品牌識別一致、部署成功、無明顯效能退化。

### P2 — 品牌獨立資源與量測（第 2–3 週，可並行）

- [ ] 評估建立 GitHub Organization，個人管理者保留 owner；採最小權限與備援管理策略。
- [ ] 評估品牌自訂網域、品牌 Email 別名/轉寄成本與 DNS 方案。
- [ ] 先驗證新網址、TLS、舊網址導流、資源路徑、SEO、CI/CD、外部整合及回退方案，再由管理者決定是否轉移 repository 或切換網域。
- [ ] 設定品牌專屬 Search Console 與適當的流量分析資源；考量隱私與必要同意機制。
- [ ] 設計社群 UTM 命名、事件及週報格式；記錄初始基準。

**驗收：** 量測能區分自然搜尋與各社群來源；若搬遷，須有經過驗證的舊連結相容性和回退方案。

### P3 — 內容資產再利用與社群啟動（第 3 週）

- [ ] 盤點既有文章：主題、讀者難度、時效性、可視化程度、是否需要重新驗證與更新。
- [ ] 建立內容欄目：研究室（深度研究）、圖解（知識圖卡）、工具箱（工具教學）、實測（比較）、新知（趨勢）、教室（入門）。
- [ ] 建立統一素材模板：社群頭像、封面、文章封面、6–8 張圖卡、短文、短影音版型、吉祥物表情及動作庫。
- [ ] 製作品牌介紹及第一批 3–5 篇既有文章的衍生素材；每份保留原文連結與正確出處。
- [ ] 初期聚焦 Threads 和 Instagram；同步使用 LinkedIn 的專業長/短文視營運量能而定。
- [ ] 管理者核可正式社群發布方式及首波素材；不因建立草稿即視為已發布。

**驗收：** 一篇原始文章可產出可發布的短文、知識圖卡及導流連結；每個渠道的格式與品牌一致。

### P4 — 穩定營運與迭代（第 4 週起）

- [ ] 建立週內容排程：建議每週 2–3 則短文、1–2 組圖卡、1 篇長文或更新，依實際量能調整。
- [ ] 延續研究工作流：官方資料/GitHub/技術社群 → 實測與截圖 → 競品/替代方案 → 入門文章 → 驗證與發布。
- [ ] 一篇文章以 5–10 分鐘閱讀為目標，長題材拆系列並互相連結。
- [ ] 每週追蹤觸及、收藏、分享、社群連結點擊、網站訪客、自然搜尋、回訪及內容完成情況（依可得資料）。
- [ ] 前 4 週先收集基準，再設定下一階段可驗證的成長目標；避免將主觀預測當成流量承諾。
- [ ] 每週更新 Roadmap：完成項目、證據連結、阻礙、下一步及調整原因。
- [ ] 視成效評估電子報、短影音、開源專案、合作及其他作者加入，不急於商業化。

**驗收：** 具備持續內容產出與可量測的社群導流循環，並能根據實際數據調整選題。
